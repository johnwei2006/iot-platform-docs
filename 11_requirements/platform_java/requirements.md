## 1. 背景与目标

`platform_java` 是平台的**后台业务平台**，承担设备管理、业务处理、规则引擎与对外
REST API，是 Web 前端与小程序的服务提供方，也是设备数据的最终汇聚与处理节点。

> 当前 `2_codes/platform_java/` 为空，本需求基于总体架构（`../../system-overview.md`）
> 反推，待代码落地后以实际实现为准。

## 2. 范围

### 含

- 设备全生命周期管理：注册、鉴权、状态、元数据。
- 消费来自 `dtm` 的上行数据，持久化与索引。
- 业务规则处理（阈值、告警、转发）。
- 对外 REST API：供 `web_vue3` 与 `mini_uniapp` 调用。
- 下行指令下发：经 `dtm` → `ProxyTcp` → 设备。
- 用户/角色/权限（运营人员与终端用户）。

### 不含

- 设备 TCP 直连接入（归 `ProxyTcp`）。
- 前端展示（归 `web_vue3` / `mini_uniapp`）。

## 3. 功能需求（FR）

| 编号 | 描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-platform-001 | 设备注册与鉴权 | P0 | 未授权设备拒绝接入；注册信息可管理 |
| FR-platform-002 | 设备状态与元数据查询/更新 | P0 | 设备列表、详情、状态可查可改 |
| FR-platform-003 | 上行数据接入（消费 `dtm`）与持久化 | P0 | 数据完整入库，可检索 |
| FR-platform-004 | 业务规则与告警生成 | P1 | 触发条件可配置，告警可推送 |
| FR-platform-005 | 下行指令生成与下发 | P0 | 指令经 `dtm` 可靠到达设备 |
| FR-platform-006 | 用户/角色/权限管理 | P1 | 运营/终端两类用户权限隔离 |
| FR-platform-007 | 对外 REST API（统一响应、鉴权） | P0 | 供前端/小程序稳定调用 |
| FR-platform-008 | 设备数据报表与统计 | P2 | 按时间/设备维度统计 |

## 4. 非功能需求

| 编号 | 维度 | 目标 |
| --- | --- | --- |
| NFR-platform-001 | 性能 | 上行数据高吞吐消费 |
| NFR-platform-002 | 可用 | ≥ 99.9% |
| NFR-platform-003 | 安全 | 接口鉴权、数据权限隔离 |

## 5. 依赖与接口

- 上游：`dtm`（上行数据）、`ProxyTcp`（下行指令经 `dtm` 转发）。
- 下游：`web_vue3`、`mini_uniapp`（REST API）。
- 接口契约：`../../12_design/api-design.md`。

## 6. 验收标准

- 设备上下行全链路打通；API 可被前端/小程序调用并通过鉴权。
