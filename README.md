# IoT 物联网平台 · 智能体实现技术体系（文档仓）

本仓库是 **通用 IoT 物联网设备接入与管理平台** 的**文档仓**，承载覆盖
**业务需求 → 设计开发 → 测试 → 部署 → 运维** 全生命周期的技术体系文档。

文档作为后续各代码组件"智能体实现"的蓝图与规范：每个组件在落地代码时，
都应以本仓对应文档为事实依据，确保需求、设计、测试、部署、运维一致且可追溯。

---

## 一、智能体实现技术体系说明

"智能体实现（Agentic Implementation）"指以 **AI 智能体（Agent）** 为执行主体，
按软件生命周期分角色、分阶段推进平台建设的工程方法。

### 1.1 生命周期与智能体角色

| 阶段 | 目录 | 主导智能体角色 | 核心产出 |
| --- | --- | --- | --- |
| 业务需求 | `11_requirements/` | 需求分析师 Agent | 业务需求、组件功能需求、验收标准 |
| 设计开发 | `12_design/` | 架构师 Agent + 开发 Agent | 总体架构、报文协议、数据模型、接口契约、组件设计 |
| 测试 | `13_test/` | 测试 Agent | 测试策略、组件测试计划、测试报告 |
| 部署 | `14_deploy/` | 部署/DevOps Agent | 部署架构、组件部署手册、CI/CD |
| 运维 | `15_maintain/` | 运维 Agent | 监控告警、运维手册、应急预案 |

### 1.2 协作原则

- **单一事实来源**：架构、报文协议、数据模型、接口契约集中定义在 `12_design/`，
  各组件设计仅描述自身并**引用**而非重写，避免口径漂移。
- **模板化一致**：五类文档（需求/设计/测试/部署/运维）统一模板，结构一致，
  便于智能体批量生成与补全，也便于人工评审。
- **相对路径互链**：文档间一律使用相对路径链接，保证仓库迁移后链接不失效。
- **图即代码**：架构图 / 流程图 / 时序图一律用 Mermaid 代码块，GitHub 原生渲染。

## 四、使用方式

1. **新人 onboarding**：先读 `README.md` → `system-overview.md` → 对应组件的
   `12_design/<组件>/design.md`。
2. **智能体执行**：按生命周期逐目录推进，先完成上游（需求/设计）再开展下游
   （测试/部署/运维）；每个组件文档互为引用，不重复定义。
3. **变更评审**：架构/协议/接口发生变更时，先更新 `12_design/` 集中定义，
   再同步各组件文档与代码。
